# RMCM 手法・検証要約

## 手順と高速化

固定した自己含有 δ 近傍を作り、中心をデータからランダムサンプリングし、最近傍への暫定割り当て、近傍内クラスタ占有率 R、R をそのまま重みにした重心更新を反復する。べき指数はない。

`R=PH` より `RᵀX=Hᵀ(PᵀX)`、`Rᵀ1=Hᵀ(Pᵀ1)`。固定 P の転置積を最初に一度だけ計算する。R を反復中に実体化する NumPy/CSR 実装と、実数上は同じ式になる。

RMCM は最適化問題に基づく方法ではなく、収束保証を持たない。目的関数に基づく RMCM2、および既存の RCM / ExRCM / FCM とは区別する。完全状態の固定点、周期、反復上限を別々の停止理由として返す。

## 公平な比較

同じ初期中心・近傍グラフ構築・距離計算・空クラスタ処理・停止条件で比較。NumPy 基準は O(E+NK) の占有率集計を使う。全体時間は入力コピー、近傍構築、前計算、反復、最終密 R を含む。Linux x86-64、Python 3.12.14、1 スレッド、7 回の中央値。Numba はウォームアップ済み。

| ケース | N / D / K | NumPy ms | CSR ms | adjoint ms | adjoint全体倍率 |
|---|---:|---:|---:|---:|---:|
| small_sparse | 1024 / 4 / 4 | 12.71 | 13.27 | 12.95 | 0.98× |
| many_points | 8000 / 3 / 12 | 173.84 | 170.15 | 139.22 | 1.25× |
| high_dimension | 2048 / 64 / 8 | 369.91 | 379.02 | 370.99 | 1.00× |
| many_clusters | 3072 / 8 / 48 | 103.85 | 102.10 | 97.24 | 1.07× |
| isolated | 4096 / 16 / 8 | 65.26 | 68.39 | 62.96 | 1.04× |
| dense_partial | 4096 / 2 / 4 | 1946.06 | 1574.97 | 1130.37 | 1.72× |
| full_graph | 512 / 8 / 8 | 30.80 | 29.60 | 29.96 | 1.03× |

密だが完全ではない近傍の例で全体 1.72×、1 反復 57.0×。後者には近傍構築・前計算・最終 R は含まれず、全体倍率として扱わない。小規模・高次元・孤立点では全体差が小さい。1.00× 近傍の差から優劣を断定しない。

## 検証と制約

- ソースとインストールした wheel の双方で 88 テスト成功（任意 Numba を含む）
- 通常 7 ケース × 4 バックエンドの 28 組はラベル・反復回数・停止理由・周期が一致。最大中心絶対誤差は 7.99×10^-15
- 転置の不均一次数例、自己辺、重複、δ 境界、空クラスタ、有理数演算で確認した真の周期 2、出力 R と重心の対応を検証
- 部分完全グラフの退化例では、約 10^-16 の中心の丸め差からラベルや停止状態が分かれた。実数上の式の同値性は、任意入力での浮動小数点軌道一致を保証しない。THEORY.md に入力を掲載
- グラフの最悪メモリは O(N²)。max_edges は候補辺数を制限するが密 N×K 出力は別。不要なら return_memberships=False
- Numba は任意。新規プロセスの例では初回 fit が約 722 ms、標準 adjoint は約 63 ms。初回コストのため既定にはしない
- Linux x86-64 / Python 3.12 検証のみ。macOS・Windows は未検証
