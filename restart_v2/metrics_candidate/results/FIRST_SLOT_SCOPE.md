# First metrics v2 slot: exact scope

These are fresh restart-v2 measurements, not historical recovery results.

- n=2,000; X dimension=64; Y dimension=2, generated by a fixed random linear projection
- float64 in both spaces; seed=20261001; k=15
- One and nine CPU/thread budgets, with affinity/environment set before worker imports
- Identical X/Y byte hashes across all eight method/budget combinations
- Three warmed real-size repetitions, separate fresh process for each method/budget; medians and MAD retained
- Baseline: exactly two actual sklearn.manifold.trustworthiness calls per timed invocation
- NumPy: sortsearch, rank-only block_rows=256, 32 MiB main scratch cap
- Numba: scan, rank-only block_rows=256
- Numba sqrt: rounded-sqrt interval scan, rank-only block_rows=256
- Every method retains full sklearn distance call shapes, per-k original neighbor selection and actual NumPy rank ties
- Exact sklearn scores match; all available integer penalties match; comparisons are outside timing
- Integer penalties: read the raw/summary JSON as authoritative (same across both budgets)

At one thread: baseline 0.322105 s; NumPy 0.257176 s (1.25x); Numba 0.095745 s (3.36x); Numba-sqrt 0.091897 s (3.51x).

At nine threads: baseline 0.328478 s; NumPy 0.286342 s (1.15x); Numba 0.080250 s (4.09x); Numba-sqrt 0.079797 s (4.12x).

The small scan/sqrt gap does not establish a robust advantage. NumPy sortsearch is not claimed to be the fastest NumPy method; a broadcast/block comparison is prepared next. Whole-process peak RSS includes runtime/JIT state and is not just algorithm workspace. All results are from this execution environment; no generic cross-OS performance claim is made.
